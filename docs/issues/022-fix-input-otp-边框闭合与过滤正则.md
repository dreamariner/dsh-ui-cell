# 022 · fix · InputOtp 的格子边框与输入过滤

## 背景

文档站上 InputOtp 的**选中格（蓝框）底部看起来没闭合**（复审截图圈出）。

## 实测（dpr=1，文档站）

逐像素导出选中格（蓝色判定：b 通道显著高于 r）：

| 边 | 修前（0.5px） |
|---|---|
| 左右竖边 | ✓ 实心 |
| 四角弧 | ✓ |
| **上横边直线段** | **整段缺失**（只有两角的弧）|
| **下横边直线段** | **整段缺失** |

即 0.5px 边框的**水平段被设备像素对齐整段吞掉**：格子顶/底的布局 Y 落在分数像素上
（本例 y=100.28），0.5px 的横线分摊到两行设备像素各 ~25-50% 透明度，再叠加 Chromium
对分数坐标边框的绘制路径，横段直接不可见；竖边恰好落在整数 X 上就正常画。
滚动位置变化会挪动分数部分 —— 所以这是「时而闭合时而断开」的抽签，选中蓝的高对比
把断口放得特别明显（灰格子的低对比看着还行，其实同样在丢）。

## 处置

**格子边框 0.5px → 1px**（`src/input-otp.css`）：≥1px 的边框无论落在哪个分数像素
都至少盖满一行设备像素，永远闭合。修后逐像素核对：四边全部实心闭合 ✓。
灰格（0.5px→1px）一并跟着变，视觉略重一线，可接受（32px 小控件，shadcn 同位也用 1px 级）。

> 仓里 53 处 0.5px 不在本次动：大面积面板/卡片的横边断一两个像素肉眼不可见，
> 只有小而高对比的控件（OTP 格子这种）才把断口放大 —— 该口径记在这里，
> 以后写小控件边框一律 ≥1px。

## 顺带修掉一个真 bug：输入过滤正则丢反斜杠

```tsx
value.replace(/D/g, '')   // ❌ 只剥字面字母 "D"
value.replace(/\D/g, '')  // ✓ 剥全部非数字
```

实测 `a1b2c3d5` 原样进格（截到 4 位变 'a1b2'）。护栏钉住（见下）。

## 护栏

新增 `tests/input-otp.spec.tsx`（7 例）：

- 输入契约：敲数字逐位点亮 + active 前进；**非数字被剥掉、超长截断**（钉 `\D` 这条）；
  填满触发 onComplete；退格删末位 active 退回；点击格子区聚焦隐形 input；
- 样式契约：格子边框 ≥1px（禁 0.5px）+ 光标动画有 reduced-motion 降级。

测试基建注记：React 受控 input 在 jsdom 里要用**原生 value setter + `input` 事件**
驱动 onChange（直接派发 `change` 事件不生效）—— 这套写法留在 spec 里当样板。
