# 009 · fix · 样式注入顺序成为隐性依赖（add note 给出依赖序）

## 背景（消费端事故回流）

dsh-pilot（消费端）项目筛选行「选中态与非选中态不和谐」：SegmentedTabs 的 tab 复用
Pill，元素同时挂 `.duc-pill` 与 `.duc-segmented-tabs-tab` 两个**同特异性**类；消费端
聚合模块恰把 pill 排在 segmented-tabs 之后，Pill 的按钮外观（bg-layer-2 底 / 24px 高 /
全圆角）把 tab 的扁平样式（透明底 / 30px 高 / radius-md）整个盖掉，筛选行「药丸套方框」
（dsh-pilot issue 011，2026-11-10）。

机制层的原因在本仓：上游 CSS Modules 靠哈希类名隔离，复制改名后类名共存于同一个
`<style>`，**注入顺序成了隐性依赖**，而本仓的 add note 与全部文档只说「把 styles 拼进
注入器」，从未说**按什么顺序**。

## 改动

### add note（cli/add.ts）
样式注入 note 升级：给出本次闭包的注入顺序（`expanded` 本就是后序闭包，deps 先于本体，
直接作为顺序交给消费端）+ 规则说明（同特异性共存类，后者胜；复用别件的组件排后面）+
实证出处。复用别件外观的不止 segmented-tabs→pill，terminal-block 复用
pill / state-dot / command-text 同理，note 用通用表述。

### 护栏测试（tests/registry.spec.ts，+2）
- 机制钉：`resolveDependencies(['segmented-tabs'])` 里 pill 必须先于 segmented-tabs
- 产物钉：`addComponents(['segmented-tabs'])` 的 note 必须含 `pill → segmented-tabs`
  且写明「同特异性」

### 文档同步（四处）
README 与 AGENTS.md 的「复制后插件侧两件事」第 2 条、手册 ③ 接线细节加一条 +
④ 高频坑加一行（症状 / 原因 / 处置）、wiki 01 新手教程第 2 步的聚合示例后补顺序规则。
手册 version 1.0.0 → 1.1.0；包版本 0.3.0 → 0.3.1。

## 结果

## 教训

1. **转换改变语义**：CSS Modules 的隔离语义依附哈希类名；duc- 化改名把「互不冲突」
   变成「共存互斥」，任何依赖哈希隔离才安全的东西（层叠顺序）都要重新显式建模。
   本仓 002 已把类名改成 `前缀 + 组件名段` 解决**重名**，这次补上的是**顺序**。
2. 消费端事故要回流到工具层：dsh-pilot 011 的修复是消费端自救（手调顺序 + 本地护栏），
   本 issue 把规则下沉进 add 的交付物与手册，后续消费端从第一次 add 就拿对顺序。
