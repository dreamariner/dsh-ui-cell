# 013 · fix · 公开面清理本机路径与个人私有信息

## 背景

本仓是**公开仓**（GitHub），文档站会发到 GitHub Pages，npm 包会发到 registry。
文档站的 `PathLabel` 演示里写了本机的绝对路径（形如 `/Users/<用户名>/Documents/<目录>/AGENTS.md`），
连用户名与目录结构一起贴到了公开面上。这是无意泄露，但公开面一旦发布就是公开的。

同类风险在本仓有三类：

| 类别 | 实例 |
|---|---|
| 本机绝对路径 | `docs/wiki/demos/atoms.tsx`（PathLabel 示例）、`docs/wiki/demos/content.tsx`（终端块的 cwd）、`scripts/import-markdown-family.mjs`（DSH_CHECKOUT 未设时的兜底默认值） |
| 个人私有项目与人格相关名字 | `docs/issues/002/003/004/005/007` 里的个人称谓、内部插件仓名与人格相关称谓 |
| 生成物 | `docs/wiki/index.html`（文档站产物，含上面全部内容） |

最后一条最要紧：**生成物是被发布出去的那一份**，源文件改了但没重建站点，等于没改。

## 方案

### 一、清理

- 演示里的路径换成中性示例：`/workspace/demo/...`（不出现任何用户目录）
- `scripts/import-markdown-family.mjs` 的兜底默认值删掉，改用 `scripts/lib/paths.mjs` 的
  `dshCheckout()`：**显式指定、无默认推导**（本来就该这样，见 paths.mjs 的头注）
- issue 文档里的个人称谓与私有仓名改成通用表述（「作者」「姊妹插件仓」「内部插件仓」「个人笔记」）

### 二、护栏（`tests/registry.spec.ts` 新增一组）

扫「活面」（源码 / 脚本 / 技能手册 / 文档含 docs/issues / tokens / 生成物 index.html）：

| 检查 | 抓什么 |
|---|---|
| 不写本机用户目录的绝对路径 | `/Users/<名>/` 、`/home/<名>/` 、`C:\Users\<名>\` |
| 不出现个人私有项目与人格相关名字 | 人格名、其插件仓名、人格相关称谓 |

生成物 `docs/wiki/index.html` 在扫描面里：**改了源文件没重建站点，护栏会红**。
这条护栏上线当天就咬了一次（重建前的 index.html 里还留着旧路径），属预期行为。

历史 git blob 不在扫描面里：改写历史不是本仓的职责（内部规范 A 方案：历史保留不改写）。

## 影响面

- 只改公开面内容与新增护栏，不动组件源码与上游 DSH
- 演示里的路径换了写法，PathLabel 的观感不变（仍是「目录前缀弱化 + 末段强调」）
- `import-markdown-family.mjs` 现在必须显式给 `DSH_CHECKOUT`，不设即报错退出（原先靠本机兜底路径跑）

## 结果

- `pnpm test` 82 通过 1 跳过（含新增 2 条护栏）
- 重建后的 `docs/wiki/index.html` 里 `/Users/` 命中 0 次
- 实机核对：PathLabel 演示显示 `/workspace/demo/src/components/button.tsx`，页面无本机路径
