# 002 · 全面复审修复：类名组件段 + keyframes 前缀 + 依赖闭包 + vendor 锚派生

## 背景

001 落地后对全仓做了一次对抗性复审（2026-11-05），逐文件核对设计与实现。分发模型与
核心机制（类名表、token 纪律、pinned 快照、行为保真）全部成立，但抓到 2 个 P1、2 个 P2、
5 个 P3，共享一个根因：

**官方 CSS Modules 的隔离粒度是「每文件哈希」，本仓把它降级成「一个 `duk-` 前缀打天下」，
而消费端又把全部组件样式拼进同一个 `<style>`**，哈希隔离不复存在。

## 发现与修复

| # | 级别 | 发现 | 修复 |
|---|---|---|---|
| F1 | P1 | 跨组件类名冲突：input/select 都有 `.wrap`、button/input 都有 `.icon`，前缀化后 `.duk-wrap`/`.duk-icon` 各被两个组件重复定义，同文档级联后者覆盖前者。实机影响：MemoryEntry 的 toolbar 按钮 icon 被强制染成 input 定义的 tertiary 色，不继承按钮色 | `finalClassName()`：根类（与组件同名）免组件段（`.button`→`duk-button`），其余加组件名段（`.wrap`→`duk-input-wrap`）；类名表与 CSS 改写共用同函数。护栏新增「全组件最终类名跨组件唯一」 |
| F2 | P1 | registry 不建模组件依赖：单加 risk-confirmation 产出 3 个悬空导入（button/icons/modal）的坏产物，CLI 退出码 0；modal/select 同样缺 icon。首个消费者没踩坑纯因当时九组件全量一起 add | registry 条目加 `dependencies`（modal→icon；risk-confirmation→button,modal,icon；select→icon）；`addComponents` 解析传递闭包（deps 先于本体、环检测）。护栏新增「声明与实际相对导入一致」+「单加产物无悬空导入」 |
| F3 | P2 | `@keyframes modalEnter` 不改名地穿过转换器（modal.css 定义 + 两处 animation 引用），动画名是文档级命名空间，两插件同名 keyframes 后者全局覆盖前者 | `prefixCss` 对 keyframes 定义与 `animation`/`animation-name` 引用同步改名（`duk-modal-modalEnter`）。护栏两条 |
| F4 | P2 | vendor 锚写死：`dshCommit` 是手写字面量，`dshVersion` 走不存在的 package.json 字段的 fallback（永远生效）；升级重跑 vendor 后 token 列表更新而锚原地不动，清单谎报来源且 `--check` 照样过（比对的就是同一份旧字面量） | 锚改从 checkout 派生：version 取根 package.json，commit 取 `git rev-parse HEAD`。重生成后清单零 diff（同 checkout 派生同值），证明派生正确且 pinned 不变 |
| F5 | P3 | `icons.tsx` 的 `IconSlot` 无使用方，随 icon 条目复制进每个插件 | 删除（连同只为它服务的 `ReactNode` 导入与 barrel 导出） |
| F6 | P3 | `cli/add.ts` 尾部 `export { basename, dirname }` 死导出（导入未用，纯转发） | 删除 |
| F7 | P3 | spec 头注释仍写「gen-tokens.mjs」（脚本已改名 vendor-tokens.mjs） | 更正 |
| F8 | P3 | registry.json `$schema` 指向 shadcn 官方 schema，但 status/upstream/dshVersion/dependencies 均不在该 schema 里，严格校验器会拒 | 删除装饰性引用 |
| F9 | P3 | token 纪律正则的色值盲区：hsl/hsla/oklch/oklab/lab/lch 能穿过（hex/rgb/具名色有拦） | 补 `\b(?:hsla?|oklch|oklab|lch|lab)\(`。**color-mix( 不禁**：tag.css 按官方同款写法用它混合 alias token 与 transparent，参数是 token 非字面色 |
| F10 | P3 | `cssClassNames` 与 `prefixCss` 判定不一致：前者数任意位置的 `.foo`，后者只改写选择器位置；链式类 `.a.b` 会进表但不改写 | 两函数统一为同一套「选择器位置」判定；另加护栏「组件 CSS 无链式类选择器」（当前无此形态，把盲区变成会响的 tripwire） |
