# 01 · 新手教程：从零把组件跑进你的 DSH 插件

这是一篇 shadcn 式的上手教程：不装组件库，**把组件源码复制进你的插件**，源码归你所有。
全文以「给一个 cordis 插件接一个记忆面板」为线索，十分钟走完。

> 前置认知（30 秒）：DSH 官方规范禁止第三方插件 load 官方 client 包，sanctioned 路径是
> 「复制 primitive 的 markup/CSS/行为进插件、类名改前缀、样式只引用 `--dsw-alias-*` token」。
> dsh-ui-kit/cell 把这条路径做成了工具。名字里的 cell 即论点：**复制即独立**。

## 第 0 步 · 安装

```bash
npm i -D @dreamariner/dsh-ui-cell
```

它是 devDependency：`add` 之后你与它再无运行时瓜葛（运行时依赖只有 react + clsx，
都会被插件自己的 bundle 打包）。

## 第 1 步 · add 复制组件

```bash
npx dsh-ui-cell add button input tag segmented-control modal risk-confirmation select textarea icon \
  --to packages/my-plugin
```

产物落在插件的 `src/client/ui/`：

```
src/client/ui/
├── button.tsx / button-css.ts      # css 会转成 <name>-css.ts（样式文本 + 类名表）
├── input.tsx / input-css.ts
└── …
```

两个机制你应当知道：

1. **依赖闭包自动带上**：`add risk-confirmation` 会同时复制 button / modal / icon
   （deps 先于本体），产物无悬空导入。
2. **类名已带前缀 + 组件名段**：input 的 `.wrap` → `duk-input-wrap`，button 的根类
   `.button` → `duk-button`。跨组件绝不重名，与你插件自己的样式零冲突。

## 第 2 步 · 样式注入（panel-css 模式）

插件 client 构建没有 CSS 管线，样式走运行时 `<style>` 注入。每个 `-css.ts` 导出
`styles`（样式文本）与 `css`（类名表），把它们拼进插件已有的注入器：

```ts
// src/client/panel/panel-css.ts
import { styles as buttonCss } from '../ui/button-css.ts'
import { styles as inputCss } from '../ui/input-css.ts'
// …用哪个组件引哪个

export const KIT_CSS = [buttonCss, inputCss /* … */].join('\n')
```

注入时与手写样式拼一份：`tag.textContent = PANEL_CSS + '\n' + KIT_CSS`。

## 第 3 步 · 使用组件

```tsx
import { Button } from '../ui/button.tsx'
import { IconDatabaseOutlineRegular } from '../ui/icons.tsx'

<Button variant="toolbar" size="sm" icon={<IconDatabaseOutlineRegular size={13} />}
  onClick={openTab}>
  {t('entry.title')}
</Button>
```

**类名表为什么好用**：表的键是原类名、值是最终类名（`'primary': 'duk-button-primary'`），
所以官方源里的 `css[variant]` 动态索引访问原样可用——add 时 tsx 一个字都不用改。

## token 纪律（写样式时的三条铁律）

1. 只引用 `--dsw-alias-*` / `--dsw-radius-*` 等稳定语义面；禁 static/specific/字面色
2. token 名必须真实存在：拼错 = 整条声明静默丢弃（零报错），kit 的存在性护栏按 pinned
   清单逐个校验
3. 复制进插件后必须带前缀——add 已经做完，**不要手抄组件绕过它**

暗色不用你管：样式全部走 token，宿主 `body[data-ds-dark-theme]` 一切，全组件跟随。

## 升级

- kit 发新版本 → `add --force` 重跑（同名文件覆盖；类名表机制保证 tsx 不用动）
- DSH 升级 → kit 按 upstream 逐组件重 diff（`vendor:check` 看 token 增删），你自己
  决定要不要跟进；不跟进也不会坏（唯一硬触发点是官方删 token，`vendor:check` 会红）

## 常见坑

| 坑 | 说明 |
|---|---|
| 手抄组件绕过 add | 前缀/类名表/keyframes 改名全在转换器里，手抄必撞命名空间 |
| 同一 `<style>` 里手写裸类名 | 消费端所有样式共一个命名空间，裸名会与 kit 类或彼此相撞 |
| 把 kit 当运行时依赖 import | add 复制走的是源码；运行时 import kit = 违反官方禁令的等价物 |
| 自改 `*-css.ts` | 生成物勿手改；改样式回 kit 的 `src/*.css` 再重新 add |
