# 03 · 依赖分层与 add 的依赖交接

> 这一页讲「组件分两档」这件事：什么时候会带进 npm 依赖、add 时会发生什么、
> bundle 会变大多少。

## 一、为什么要分两档

本仓最早定的是「所有组件零运行时依赖」。那条纪律是我自己设的（**DSH 官方并没有这个要求**），
官方唯一的硬约束是 `practices.md:35`：**不许 load 官方 Harness Client 包**，普通 npm 依赖随便带。

零依赖的代价很实在：markdown 家族（MarkdownText / ReadBlock / WebBlock / QuotePreview /
DetailDocument）被暂缓，代码块永远没有语法高亮，diff 是手写 LCS，ANSI 的 truecolor 输出
还是坏的（`rgb(rgb(r,g,b))`，浏览器整条丢弃）。

现在分成两档：

| 档 | 是什么 | 依赖 | 谁在用 |
|---|---|---|---|
| **`atom`** | 原子件：按钮、输入、下拉、分段控件、弹层、卡片… | 零重依赖（只用 react + clsx） | 绝大多数插件 |
| **`content`** | 内容块：markdown 家族、代码块、差异块、终端块 | 带 npm 重依赖（shiki / katex / diff / anser / micromark 家族） | 需要渲染富文本的插件 |

**默认档是 atom**。只有你明确 `add` 了 content 档的组件，才会带进重依赖。

## 二、add 时会发生什么

```bash
npx dsh-ui-cell add markdown-text --to packages/my-plugin
```

1. **依赖闭包自动展开**：markdown-text → code-block / code-toolbar / code-highlighting /
   hover-card / image-lightbox / image-preview / icon / tooltip / clipboard…（deps 先于本体）
2. **文件复制**：源码 + 样式（`.css` 转成 `<name>-css.ts`，导出类名表与样式文本）
3. **依赖交接**：CLI 比对消费端的 `package.json`，把**缺失的 npm 包**报出来：

```
· 消费端缺这些 npm 依赖（复制过去的是源码，裸 import 要能解析到包）：
  shiki@4.4.3 @shikijs/langs@4.4.3 katex@^0.18.7 mdast-util-from-markdown@^2.0.3 …
  装：pnpm add shiki katex mdast-util-from-markdown …
  或 add 时加 --with-deps 直接写进 package.json
```

**默认只提示、不写文件**（改你的仓库是有副作用的事，必须你明示）。
想让它直接写进 `dependencies`：

```bash
npx dsh-ui-cell add markdown-text --to packages/my-plugin --with-deps
```

写完记得跑一次安装。

## 二之二、原样注入的样式（rawStyles）

有两类样式的类名**不能加前缀**，它们是第三方契约：

| 文件 | 契约 | 谁需要它 |
|---|---|---|
| `katex.css` | `.katex` / `.katex-display`（KaTeX 自己吐的类名） | markdown-text |
| `shiki.css` | `--shiki-token-*`（shiki 的 css-variables 主题变量） | code-highlighting |

这两个文件走 `rawStyles` 通道：样式文本**原样**注入，不产生类名表（表是空的，
组件也用不上它们）。

**关键：它们没有组件 tsx 引用。** 消费端是「显式 `import { styles }` 拼进
`<style>` 注入器」的模式，而 raw 样式是**孤儿**——add 交付时会在 note 里点名：

```
· 原样注入的样式模块（第三方契约类名，不加前缀）：katex-css.ts、shiki-css.ts ——
  它们没有组件引用，要自己 import { styles } 一起拼进注入器，
  漏了会丢样式（公式不排版 / 代码高亮没颜色）。
```

漏拼是**静默**的：没有报错，只是公式塌成一坨、高亮没有颜色。护栏盯着这件事
（raw 样式模块必须出现在 add 的 note 里）。

> `shiki.css` 宿主 ui-theme 已经全局注入过一份，重复注入无害。
> `katex.css` 宿主**不提供**（官方是靠包内 `import 'katex/dist/katex.min.css'`），
> 第三方插件必须自己带上。

## 三、bundle 会变大多少

content 档的组件带的是**运行时依赖**（会进你的 client bundle）：

| 依赖 | 量级 | 什么时候加载 |
|---|---|---|
| shiki（core + 8 种语法） | 数百 KB ~ 1MB 级 | 首次高亮时（语法是静态打包的，不走动态 chunk） |
| katex | 数百 KB（数学排版引擎） | 第一次渲染公式时（`katex` 本身是同步 import，会进 bundle） |
| micromark / mdast 家族 | 数十 KB | 解析 markdown 时 |
| diff / anser | 数十 KB | 算差异 / 解析 ANSI 时 |

**建议**：只用原子件的面板（按钮、输入、弹层）保持零负担；确实要渲染 markdown 的面板
（工具结果、日志、文档预览）才加 content 档组件。

**一个折中**：如果只想要「代码块带高亮」而不要完整 markdown 家族，可以只
`add code-block`（依赖 shiki，不依赖 micromark 家族与 katex）。

## 四、几个容易踩的点

| 坑 | 说明 |
|---|---|
| 忘了装依赖 | 症状是**消费端编译报错**（`Cannot find module 'shiki'`），不是运行时才炸 |
| `--with-deps` 写了但没安装 | 写进 package.json 了，还得跑 `pnpm install` |
| **raw 样式没拼进注入器** | **静默失败**：公式不排版 / 代码高亮没颜色。add 的 note 会点名，照着 import `styles` 一起拼 |
| tsconfig 少 `DOM.Iterable` | markdown 的 KaTeX 渲染要遍历 DOM 集合，少了这个 lib 会报 `NamedNodeMap must have a Symbol.iterator` |
| 以为 markdown 支持流式 | 本仓的 markdown 是 **settled 全量渲染**（第三方面板不是流式场景），没有增量解析臂 |
| 公式字体走 CDN | KaTeX 的 `@font-face` 指向 jsdelivr（锁 katex 版本），**离线环境公式降级**（无字体，结构仍可读） |
| `labels` 要 memo 化 | `MarkdownText` 的 `labels` 每次换 identity 会重建整棵渲染树（官方同款约束） |

## 五、依赖档位怎么查

```bash
# 看某个条目属于哪档、带什么依赖
node -e "const r=require('./registry.json'); console.log(r.items.find(i=>i.name==='markdown-text'))"
```

registry.json 是权威清单（`tier` / `npmDependencies` / `dependencies` / `upstream` 四个字段）。
护栏会强制：atom 档不得声明 npm 依赖、content 档的闭包必须带依赖、声明与源码里的裸 import
双向一致（`@types/X` 算满足 `X`）。
