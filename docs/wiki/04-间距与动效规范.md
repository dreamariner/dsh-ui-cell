# 04 · 间距与动效规范

> 本篇讲**本仓自有件**（41 件，`registry.json` 里 `upstream` 为空的那些）的空间与时间规范。
> 官方保真复制件（53 件）不在此列：它们保真跟随上游 DSH，DSH 升级时按 `upstream` 字段逐组件 re-diff。

## 一、这套规范与官方是什么关系

官方 DSH 把设计 token 的归属写得很清楚，本仓是在那个分工里补位，不是另起一套：

| 维度 | 官方拥有 | 本仓做什么 |
|---|---|---|
| 间距语义（组内外关系、可见留白、分组判据） | `.agents/skills/dsh-client-ui-ux/references/spacing.md`、`docs/ui-design-review-cases.md` §2 | **不改写**，只引用；本规范不重复官方规则正文 |
| 间距数值刻度 | 官方明确不给（spacing 参考末句：This skill defines no numeric scale；SKILL.md：numeric scales stay with their implementation owners） | **本仓定义** `--dsh-space-*`，作为第三方插件组件的实现方补齐这块空地 |
| 动效 token（时长与缓动） | `ui-theme`（`docs/web-styling.md`：shared colors, typography, elevation, and motion belong to the theme package） | **直接复用**官方四个 token，本仓不新增任何全局动效变量 |
| 动效语义映射（哪一档用在哪） | 官方无 | **本仓定义**（三档 → 交互类型映射表） |

一句话：**语义归官方，数值归实现方，动效只借官方的面。**

## 二、间距

### 刻度

4px 底座，2px 半步（小值区），定义在基础层 `src/foundation.css`：

| 变量 | 值 | 语义角色 |
|---|---|---|
| `--dsh-space-1` | 1px | 发丝级缝隙 |
| `--dsh-space-2` | 2px | 图标与文字、极紧组内 |
| `--dsh-space-4` | 4px | 组内元素（紧） |
| `--dsh-space-6` | 6px | 组内元素（中）、控件内紧凑留白 |
| `--dsh-space-8` | 8px | 控件内边距、卡片内边距 |
| `--dsh-space-12` | 12px | 块内边距 |
| `--dsh-space-16` | 16px | 区块之间 |
| `--dsh-space-20` | 20px | 大块内边距 |
| `--dsh-space-24` | 24px | 区块分隔 |
| `--dsh-space-32` | 32px | 大留白 |

`0` 不进刻度（复位值不是节奏值，`margin: 0` 保持字面量）。
`0.5px` 是发丝描边补偿（`margin-left: -0.5px`），不是间距，保持字面量。

### 归一规则

1. **独立空间决策**（单个 padding / gap / margin 值）取**最近刻度档**；正好等距时取**较小档**
   （收紧优先：DSH 是紧凑桌面 UI，内边距变大最容易让密度失衡）。
2. **组合值**（缩进、让位这类由图标尺寸与偏移推导出来的值）**登记例外**，写明构成，
   并随其构成项同步更新。官方 spacing 参考强调「距离由关系决定，不是由数值决定」，
   组合值的正确性在关系里，不在它落在哪一档。
3. 官方件（保真复制）走例外表，值不动。

当前的三处组合值例外：

| 文件 | 值 | 构成 |
|---|---|---|
| `select.css` | 28px | 8（右偏移）+ 14（chevron 图标）+ 6（图标与文字的间隔） |
| `collapsible.css` | 28px | 8（触发器左内边距）+ 14（chevron）+ 6（间隔） |
| `accordion.css` | 34px | 12（触发器左内边距）+ 14（chevron）+ 8（头部 gap） |

共同结构是「触发器左内边距 + 图标尺寸 + 图标与文字的间隔」，作用是让内容与触发器文字对齐。
改了构成项（比如触发器内边距），缩进要同步改，否则对齐关系就断了。

### 组内 / 组间的关系（这一条官方说了算）

刻度只管数值，**关系**归官方规则，本仓照办：

- 没有显式分隔线时，相邻两组之间的可见间隔必须明显大于组内间隔（相等只是下限）。
- 标题要更靠近自己那一组的内容，而不是靠近前一组的末尾。
- 「组」按语义划分（一个对象 / 一个动作 / 一个重复单元），不按 DOM 兄弟节点划分。
- 判断看**渲染后的可见留白**（含 padding、line-height、字形留白、边框），不是 CSS margin 数值。

官方参考：`dsh-client-ui-ux/references/spacing.md`、`docs/ui-design-review-cases.md` §2。

### 字号与控件让位（间距的另一半，2026-11-18 起）

行距看着不对时，多半不是间距值的问题，是**字号与让位**：

| 规则 | 说明 |
|---|---|
| **文字不跟随宿主字号** | 组件写 `font: inherit` = 大小由嵌入它的宿主决定。DSH 应用与文档站的 body 都没有显式字号（浏览器默认 16px），于是控件会比显式 13px 的标签大一号，而且同一个组件在不同宿主里长得不一样。自有件必须钉在主题档位上（`var(--dsw-font-s-14)` 等），官方内容块（markdown / code / json）跟随宿主是有意为之，不在此列 |
| **成对的「标签 + 控件」要同档** | 标签用详情档 13px，控件用标准档 14px（大一档是层级，不是错误）；两者差两档以上就是排版事故 |
| **按钮的 UA padding 要清** | UA 的 `padding: 1px 6px` 会把行高撑高 3px，于是 `gap: 6px` 之外又多出 3px：**间距写在 CSS 里，却不由 CSS 决定** |
| **原生控件的自绘图标要换掉** | 浏览器自绘的下拉箭头**不随字号缩放**（控件归到 14px 档后它显得比文字还重）、颜色是纯黑、离右边框约 12px。实测 Chromium 的原生箭头**不随 `padding-right` 移动**（12px 与 28px 两档箭头位置一致），CSS 挪不动它 → 只能换自定义图标：`appearance: none` 收掉自绘箭头，右侧挂 DSH chevron（14px 细线、tertiary 色），照本仓自有 Select 的几何（图标离边 12px，右内边距 = 偏移 + 14 + 6） |

ConfigField 是这一类问题的样板（issue 014）：修前 label 13px / 控件 16px、头行 25px、
标签到控件 9px、箭头是浏览器自绘的粗黑箭头；修后 13px / 14px、头行 20px、间距 7px
（6px gap + 1px 降部）、箭头换成 DSH chevron，且原生 select 自带的内部高度算式
（31.5px）换成与同字段文本控件一致的 35px。

## 三、动效

### 三档映射

底座是官方 token，本仓只定「哪一档用在哪」：

| 交互类型 | 用哪档 | 值 |
|---|---|---|
| 即时反馈：悬停、按下、聚焦、选中、数据到达 | `--ds-transition-duration-fast` | 100ms |
| 状态切换：展开收起、显隐、开关 | `--ds-transition-duration` | 200ms |
| 大面积位移：面板进出 | `--ds-transition-duration-slow` | 300ms |

缓动统一 `var(--ds-ease-in-out)`（官方唯一 easing，Material 标准曲线 `cubic-bezier(0.4, 0, 0.2, 1)`）。

### 循环节律豁免

呼吸、旋转、闪烁这类 `infinite` 动画不是交互时长，塞进三档反而不对：

| 组件 | 动画 | 处理 |
|---|---|---|
| skeleton | `skeleton-pulse 1.6s var(--ds-ease-in-out) infinite` | 字面时长保留 |
| progress 不定态 | `progress-slide 1.4s var(--ds-ease-in-out) infinite` | 同上 |
| spinner | `spinner-rotate 700ms linear infinite` | 匀速旋转，`linear` 正确 |
| input-otp 光标 | `otp-caret 1s steps(2) infinite` | 离散闪烁，`steps()` 正确 |

豁免的前提是**必须配 `prefers-reduced-motion` 降级**。

### 可动属性白名单

默认只许动：`transform` / `opacity` / `color` / `background-color` / `border-color`。

结构性尺寸变化（`width`、`grid-template-rows`）会逐帧触发布局，登记例外：

- `sidebar` 的 `width`（侧栏收展，结构上就是改宽度）
- `accordion` 的 `grid-template-rows`（0fr → 1fr 的展开）

口径：**要动布局就别用 transition 改尺寸，改用 transform**；做不到就登记例外并写明理由。

### 降级

每个带动画的组件必须有 `prefers-reduced-motion: reduce` 块（护栏会查）。
自建组件时：长循环动画（骨架 / 不定态进度 / 呼吸）关掉，短过渡改成 `transition: none` 直接到位。

### 相位状态机（进出场动画）

出场动画要播完才卸载 DOM。两个样板：

| 组件 | 场景 | 做法 |
|---|---|---|
| sheet（issue 008） | 面板进出（滑入 + 遮罩淡入） | `mounted`（DOM 在不在）与 `phase`（`open` / `closed`，写进 `data-state`）分开管；关闭时 DOM 留着播出场动画，播完（`animationend`）才卸载 |
| disclosure-row（issue 015） | 折叠行内容展开收起 | 同上；高度用 `grid-template-rows: 0fr → 1fr`（与本仓自有 Accordion 同一手法）+ 淡入淡出 |

共同要求：

- 相位切换必须在渲染期做（React 官方「按 props 调整 state」写法），不能在 effect 里
  （effect 里切会让 DOM 比 `open` 晚一个提交，`useModalLayer` 的 layout effect 跑在 DOM 出现之前，
  层级栈不注册，Escape 关不掉）；
- 降级与兜底：`prefers-reduced-motion` 时直接卸载（样式关了动画就没有 `animationend` 事件，
  信号来自共享条目 `use-prefers-reduced-motion`），出场段另有定时器兜底（动画事件没来也照卸）。

其余组件若要补进场出场动画照此办理。

## 四、护栏

`tests/registry.spec.ts` 里的「间距与动效规范」一组（issue 012 起）：

| 检查 | 抓什么 |
|---|---|
| 基础层刻度与期望表一致 | 改刻度只改一处（两处一起改，否则红） |
| 基础层被 add 每次都带上且排第一 | 漏注入 = `var(--dsh-space-*)` 解析失败 = 静默掉样式 |
| 引用的 `--dsh-space-*` 都在基础层有定义 | 档名拼错 = 静默失效 |
| 自有件间距声明不写 px 字面量 | 新增的随手数值（组合值登记例外） |
| 自有件过渡只许官方三档时长与官方缓动 | 新增的随手时长与随手曲线 |
| 带动画的自有件都有 reduced-motion 降级 | 漏降级 = 对动效敏感用户是硬伤 |
| 自有件的文字不跟随宿主字号 | `font: inherit` = 控件大小随宿主漂移 |
| 渲染原生 `<select>` 的组件要收掉自绘箭头 | 浏览器箭头不随字号缩放，且 CSS 挪不动 |

官方保真复制件不参与这组检查（保真优先）。

## 五、消费端要做什么

`add` 会自动带上基础层并把它排在样式注入顺序**第一位**：

```
src/client/ui/
├── foundation-css.ts   # ← 间距刻度，先注入
├── button.tsx / button-css.ts
└── …
```

把 `foundation-css.ts` 的 `styles` 拼进注入器的**第一段**：

```ts
import { styles as foundationCss } from '../ui/foundation-css.ts'
import { styles as buttonCss } from '../ui/button-css.ts'

export const PANEL_CSS = [foundationCss, buttonCss].join('\n')
```

漏了 foundation：组件里的 `var(--dsh-space-8)` 解析失败 → 那条声明被静默丢弃 →
间距全没了，但**零报错**。这是最隐蔽的一类失败，务必把 foundation 拼在最前。
